# codingAgent Bonus 需求与路线图

## 1. 文档目的

本文档记录 MVP 主体之外、适合推免面试与两分钟演示视频的增强模块。Bonus 功能必须建立在现有 Agent 循环、工具、会话、上下文和 TUI 之上，不得以牺牲主体稳定性换取展示效果。

开发约束：

- 不使用 Agent 框架或服务端托管文件、代码执行能力；
- Windows、macOS 行为一致；
- 每个模块使用独立的线性堆叠分支，先测试后实现；
- 新模块维持 statement coverage ≥ 85%、branch coverage ≥ 75%；
- 每个模块必须能在 15～35 秒的视频片段内展示其价值；
- 默认不自动执行 Git 提交、推送或其他不可逆外部操作；
- Skill 内容属于本项目自行设计的工作流提示，不复制第三方项目源码或提示词。

## 2. 优先级评分

评分采用 1～5 分，演示性和编码价值越高越好；成本与风险越低越好。

| 优先级 | 模块 | 演示性 | 编码价值 | 成本 | 风险 | 结论 |
|---|---|---:|---:|---:|---:|---|
| B1 | 内置 Skills 与 `/skills` | 5 | 5 | 3 | 2 | 首选实现 |
| B2 | Agent 任务计划与进度卡片 | 5 | 4 | 3 | 2 | 第二选择 |
| B3 | Git 变更摘要与只读审查工具 | 4 | 5 | 2 | 2 | 高性价比 |
| B4 | `/init` 项目记忆向导 | 4 | 4 | 2 | 2 | 时间允许实现 |
| B5 | 重复调用/无进展检测 | 3 | 5 | 3 | 3 | 稳定性增强 |
| B6 | 工具输出实时流式展示 | 4 | 4 | 4 | 4 | 时间充足再做 |
| B7 | 外部 MCP stdio Client | 5 | 4 | 5 | 5 | 截止前不优先 |

## 3. B1：内置 Skills

### 3.1 用户价值

Skill 是可发现、可检查、按需加载的编码工作流。实现遵循 [Agent Skills Specification](https://agentskills.io/specification)：每个 Skill 是独立目录，以 `SKILL.md` 为固定入口，并可包含 `scripts/`、`references/` 和 `assets/`。它不创建第二个 Agent，也不绕过现有工具系统；其作用是把特定任务需要的步骤、约束和完成标准注入当前轮次，降低模型遗漏验证步骤的概率。

首批内置 Skill：

- `test-fix`：复现失败、定位最小根因、修改、运行针对性测试和完整回归；
- `code-review`：读取变更、按严重程度报告可复现问题，不主动修改代码；
- `project-map`：快速识别入口、核心模块、测试和依赖，生成项目结构说明。

### 3.2 功能需求

- **BONUS-SKILL-001** Skill 使用 `<skill-name>/SKILL.md` 保存，入口包含 YAML frontmatter 与 Markdown 正文，`name` 必须匹配目录名。
- **BONUS-SKILL-002** 系统启动时只加载内置、用户级和项目级 Skill 的名称、描述与来源，不预加载正文。
- **BONUS-SKILL-003** 同名 Skill 按 `builtin < user < project` 覆盖，来源必须可见。
- **BONUS-SKILL-004** `/skills` 展示可用 Skill、描述和来源。
- **BONUS-SKILL-005** `/skill <name> <task>` 在当前会话提交一个带明确边界的 Skill 任务。
- **BONUS-SKILL-006** 未知 Skill、空任务、损坏元数据返回可操作错误，不导致会话崩溃。
- **BONUS-SKILL-007** 会话事件保存用户原始任务和所选 Skill 名称，恢复后可审计。
- **BONUS-SKILL-008** Skill 正文按需注入，不应在每轮把全部 Skill 正文占满上下文。
- **BONUS-SKILL-009** Skill 不得扩大 Shell、文件或审批权限。
- **BONUS-SKILL-010** 模型可根据常驻 metadata 调用 `activate_skill`；激活后下一步才加载对应 `SKILL.md` 正文。
- **BONUS-SKILL-011** 正文引用的 `references/`、`scripts/` 或 `assets/` 文本通过 `read_skill_resource` 按需读取，并受目录逃逸、符号链接、编码和大小限制；二进制资产不会被误当作文本注入上下文。
- **BONUS-SKILL-012** `allowed-tools` 作为实验性标准字段被解析但不自动授权，现有审批策略始终优先。

### 3.3 演示脚本

输入 `/skills` 展示四个工作流；随后输入 `/skill test-fix 修复这个失败测试`。TUI 显示正在使用的 Skill，Agent 按“复现→定位→修改→验证”完成一个真实缺陷。还可用普通自然语言触发模型先调用 `activate_skill`，证明 metadata 与正文的渐进式披露。该片段可同时展示 Slash 补全、工具调用、测试执行和最终结果。

### 3.4 完成标准

- Loader、覆盖顺序、损坏文件和路径边界具有单元测试；
- `/skills`、Slash 补全和 `/skill` 具有 TUI 测试；
- Skill 选择通过 Application/CoreEvent 进入核心，不在 TUI 中拼接隐藏提示；
- 恢复后的事件记录能说明该轮使用了哪个 Skill；
- 未启用 Skill 的普通对话只增加简短 metadata 目录，不注入任何 Skill 正文。

## 4. B2：任务计划与进度卡片

### 4.1 用户价值

提供内置 `update_plan` 工具，让模型维护最多一个 `in_progress` 步骤的结构化计划。TUI 显示可折叠计划卡片，工具执行后自动刷新状态。计划属于当前任务的可观测状态，不替代 Agent 循环。

### 4.2 核心需求

- 计划步骤状态仅允许 `pending`、`in_progress`、`completed`；
- 同时最多一个步骤处于 `in_progress`；
- 计划更新持久化到 JSONL，恢复会话后重建最新计划；
- 上下文压缩摘要保留当前计划和未完成步骤；
- TUI 使用完成数、总数和当前步骤提供紧凑展示；
- 最大步骤数和文本长度受限，避免模型滥用上下文。

### 4.3 演示脚本

交给 Agent 一个包含搜索、修改、验证三阶段的任务。视频中计划卡片从 `0/3` 更新到 `3/3`，并与实际工具卡片对应。

## 5. B3：Git 只读审查工具

### 5.1 用户价值

提供跨平台、只读的 `git_status` 与 `git_diff` 工具，使 Agent 在修改前识别用户未提交变更，在完成后生成准确变更摘要。工具不执行 commit、push、reset 或 checkout。

### 5.2 核心需求

- 使用参数数组启动 Git，不经 Shell 字符串拼接；
- 支持工作区状态、暂存区 diff、未暂存 diff和指定路径过滤；
- 输出大小受限并标记截断；
- 非 Git 项目返回结构化可恢复错误；
- 路径仍受 WorkspaceGuard 约束；
- 最终回复前可由 Skill 建议运行，但不强制修改 Agent 的通用行为。

### 5.3 演示脚本

准备一个已有用户改动的仓库，让 Agent 先展示干净/脏状态，修改另一个文件后输出精确 diff 摘要，证明它没有覆盖用户工作。

## 6. B4：`/init` 项目记忆向导

扫描项目入口、依赖和测试命令，生成 `CODING_AGENT.md` 候选内容。`/init` 本身严格只读，只在对话中预览草案，绝不创建或覆盖文件；用户审阅后可另行明确要求 Agent 使用普通写文件工具保存。该功能能把一次项目探索转化为后续会话可复用的目录级记忆，同时让写入动作继续经过既有工具记录和未来的审批链路。

## 7. B5：无进展检测

对当前用户轮次内连续相同的工具名、规范化参数和稳定化结果计算指纹。第二次得到完全相同结果时，在工具结果中注入 `NO_PROGRESS_WARNING`，同时在界面和会话日志中记录警告；第三次仍无变化时，完整保存该次工具结果后终止当前轮并提示用户介入。新用户轮次重新计数。

读文件内容发生变化后不视为重复；Shell 的退出状态和输出参与判断，但不稳定的执行耗时不参与，避免同一失败命令仅因耗时不同而绕过检测。日志只持久化不可逆短指纹、工具名和重复次数，不复制可能敏感的参数与输出。

## 8. B6：工具输出流式展示

Shell 执行期间发布有界 `ToolOutputDelta`，TUI 展开并原位更新同一工具卡片，非交互 CLI 直接输出增量；结束后仍由 `ToolFinished` 用最终结果收口。stdout/stderr 分别使用增量 UTF-8 解码器，避免多字节字符跨管道分块时损坏；增量总量复用 Shell 的输出字节上限，TUI 只保留最近 12000 个字符。

增量事件只用于当前界面，不写入 JSONL；持久化仍只保存既有的脱敏、截断最终结果。每个增量在发布前经过显示脱敏；若工具参数本身触发脱敏，则整次实时流被抑制，避免命令中的凭据先从输出回显。取消沿用原进程组终止和 `tool_cancelled` 记录链路。其他工具不实现流式协议时自动回退到原有一次性结果，不改变 Tool 接口兼容性。

## 9. B7：MCP stdio Client

作为客户端连接用户明确配置的本地 MCP Server，将外部工具映射到现有 ToolCatalog，并复用审批、超时、取消、脱敏和记录链路。该模块展示性强，但协议、生命周期和跨平台测试成本高，不应挤占核心演示稳定性。

## 10. 本地线性分支计划

```text
fix/scrolling-welcome-banner       （已推送，双平台 CI 通过）
  └─ docs/bonus-roadmap            （仅本地）
       └─ bonus/b1-builtin-skills  （仅本地）
            └─ bonus/b2-task-plan       （仅本地）
                 └─ bonus/b3-git-inspection （仅本地）
                      └─ bonus/b4-memory-init （仅本地）
                           └─ bonus/b5-no-progress （仅本地）
```

每个分支只包含相对父分支的新模块提交。用户审核前不得推送 `docs/bonus-roadmap` 或任何 `bonus/*` 分支。

## 11. 推荐执行顺序

1. B1–B5 各自在独立线性分支中按 TDD 完成并通过完整回归；
2. 用户逐分支审核后，再决定哪些模块合入和推送；
3. B6、B7 风险较高，只有在主体与已完成 Bonus 稳定后再启动，不留下半成品实现。
